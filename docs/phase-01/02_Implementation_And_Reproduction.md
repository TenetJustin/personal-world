# Phase 01 · 实现与复现

状态：可运行的外立面技术 POC；照片级视觉门槛尚未通过人工验收。仅包含两张镜头涉及的湖岸和木屋外部。

## 本地运行

Node.js ≥22.18；测试机实际使用 Node 26.5。下载私有仓库需具有该仓库访问权限。

```sh
git clone git@github.com:TenetJustin/personal-world.git
cd personal-world
git switch dev/phase-01-exterior
git lfs pull
npm ci
npm run dev
```

开发地址为 `http://127.0.0.1:5173/`。生产构建：`npm run build`，再运行 `npm run preview -- --port 5174`。所有服务仅绑定 127.0.0.1；没有配置公开部署、网站域名或外部运行时 API。

- 默认标准档：2K 环境、512²反射、2048²阴影、DPR 1。
- `?quality=high`：4K 环境、1024²半浮点反射并启用 2×MSAA、4096²阴影、DPR 上限 1.5。
- `?quality=high&benchmark=1440x900`：固定实际画布及绘图缓冲为 1440×900、DPR 1；保留高档环境与阴影。较小浏览器窗口会裁切网页视口，验收工具导出的画布仍为完整 1440×900。不得把它描述为浏览器窗口本身被调整到了该大小。
- `?shot=B`：直接打开标准近景。镜头按钮立即回到固定参数；“走近木屋 / 返回湖岸”触发约 12 秒的弧长参数化路径。Esc 可暂停；系统减少动态偏好会使普通镜头切换立即完成。
- 验收工具可冻结水与草、导出原始画布、实际 MediaRecorder 录屏、相机参数和原始性能 JSON。录屏只捕获实际 WebGL 画布，不录麦克风、桌面或离线渲染。

## 渲染路线

React 19 + R3F 9 + Three r180 的 WebGL2。米制空间，Y 向上，木屋约 8.4×7m、屋脊约 6m、门高约 2.08m。近岸为真实三维地形，包含弯曲岸线、浅滩、水下坡面、局部起伏和木屋地坪；只在当前两张镜头周围构建细节。

地面使用 Poly Haven 的落针与草岩 PBR 扫描纹理，按约 3.2m 尺度铺设并混合岸边湿润层、土径。树木、草丛与苔藓岸石来自许可清单中的真实制作资产。原始树变体 C 约 50.6 万三角面；Blender 导出 50% / 12% 两档网格，空间分区使用，远处使用从源网格离线生成的四向透明贴片。它们是明确的远景代理，不是可走近的树木。没有动态距离阈值切换，因此没有伪称验证动态 LOD 交叉淡化。只沿已批准路径验证这些分区的适用性。

木屋是本项目在 Blender 中制作的外立面模型，包含圆木、独立端面 UV、门窗洞口、山墙、金属屋面接缝、门板、五金、廊台、踏步和基础。使用实测木材 PBR 与原创端面纹理。1024² AO 由 Cycles 16 samples 烘焙到独立 UV；实时强度 0.35，避免把自遮蔽压成黑洞。窗为不透光的外部反射近似，当前材质用高金属度近似反射，并非 IOR / 透射玻璃光学；该项仍需修复，没有室内。

超远山与天空来自 CC0 Alps Field 全景，不是可自由走近的山体网格。它保留真实摄影大气层次，但存在照片与三维地形衔接、视差及景观地域不完全匹配的问题。该限制是当前视觉门槛未通过的原因之一。

湖水使用 Three.js Water 的平面镜像相机和斜裁切；已阅读实际依赖代码及 MIT 许可。局部副本增加反射目标释放、HalfFloat HDR 反射和高档 MSAA。水面着色为本项目实现：小幅几何波、多个尺度的法线波、Fresnel、按解析水床深度近似吸收、透明浅滩和太阳微高光。它没有屏幕空间深度折射、体积散射或流体模拟，不能宣传为完整物理水体。

颜色纹理标为 sRGB，法线 / 粗糙度 / AO 为线性数据，照明和反射在线性空间处理，最终统一 AgX + sRGB 输出。照明探针裁剪原 HDR 的极亮太阳峰，另以对应方位的方向光负责直射。太阳仰角由源图最亮位置推导，约 42.1°；这是相对 Phase 00 名义 25–35° 的实现差异，未伪造为该角度范围。探针裁剪不是精确的太阳光谱分离。无 Bloom、无景深后处理；仅有密度 0.00065 的轻微距离雾。

## 优化与可复现资产处理

- 同类源网格 / 材质 Instancing；共享材质；固定太阳与投射者的阴影首次生成后缓存；静态空间细节分区，树木两档源网格与远处代理。
- glTF-Transform + meshoptimizer 压缩，WebP 贴图。WebP 降低传输体积，不是 KTX2 GPU 压缩；KTX2 尚未完成，不能声明显存目标已达标。
- `bakeGeometry` 在烘焙实例变换前将量化坐标展开为 Float32，防止米制坐标写回 Int16 时溢出；有针对性回归测试。
- 资源并行预取，首次显示前等待着色器编译。正式证据使用生产 bundle，不带 Vite HMR。
- React 不在每帧 setState；相机、水、草更新通过 refs / uniforms。UI 以 400ms 节流显示；监听器、录屏流、计时器、材质、纹理和反射目标有释放路径。

运行时资产已入 LFS，正常启动不需要 Blender，也不需要访问 Poly Haven。重新制作源资产时执行：

```sh
npm run assets:fetch
npm run assets:build
```

需要 Blender 5.2.2；macOS 默认使用 `/Applications/Blender.app/Contents/MacOS/Blender`，其他路径通过 `BLENDER_BIN` 指定。制作源在忽略的 `assets-source/`，临时缓存在 `work/`。`fetch_assets.py` 验证官方 MD5，变体字节区间另外保存 SHA-256；`repair_opacity.mjs` 将官方独立透明度图与颜色图合并为真正 RGBA，随后 Blender 建模 / AO、Meshopt、WebP 和 manifest 生成。`public/assets/manifest.json` 是最终文件大小 / SHA-256 与来源 ID 的依据，早期 Blender 构建日志不能替代最终 manifest。

原始 `.blend` 母版没有被声称已远程备份；脚本和运行时 GLB 已版本管理。不得自动购买 LFS 容量或上传来源不明的资产。
