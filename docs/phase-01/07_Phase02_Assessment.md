# Phase 01 → Phase 02 技术评估

**当前建议：不要进入 Phase 02。先完成人工视觉验收，并在 Phase 01 内继续美术与资产优化。**

## 已证明的部分

本机浏览器能同时运行米制湖岸、真实源网格植被与岸石、Blender 原创木屋外立面、PBR、HDR 环境、动态平面反射和细波，以及从 A 到 B 的交互相机。固定参数、原始 PNG、实际录屏与每帧性能数据均可留存。没有通过普通绿色锥体替代森林，也没有用强 Bloom / 景深 / 浓雾遮蔽模型质量。

树、岩石等制作级源资产需要有针对性的离线处理，不能把数百 MB 源文件直接塞入网页。本轮修复了透明度输入与量化坐标溢出，也验证了静态阴影缓存可在不改变标准画面的前提下降低开销。这支持继续采用 Phase 00 的路线 A：实时近景 PBR，配合受限范围的离线远景与资产制作。

## 尚未证明的部分

首要问题仍是视觉质量。地表、林下生态、树木多样性、建筑微细节、岸边水体过渡和摄影远景接合没有达到接近真实摄影的标准。高档 4K 背景改善清晰度，却带来不合格的传输预算。单台 M5 的表现不能证明最低硬件、Windows、Safari、手机或低带宽环境达标；GPU 实际显存占用未测得，不能由纹理计数换算成已通过。

全景山脉具有摄影的细节，但缺乏自由相机的三维视差；它只能作为当前受限路径的超远景。未来扩大地图或移动范围前，必须单独验证这一边界。当前不存在完整山谷地图，也没有建设室内、桌面系统、Notes、Photos 或 Projects。

## 下一次允许的工作方向

在用户审核当前证据后，优先为这两张镜头重做地表 / 林缘，补合法制作级苔藓、根系、枯枝与低矮灌木；提高树木变体多样性，重新设计远山接合；完善外立面的端面、基础与屋檐。对照参考图分别调整材质、直射 / 环境比例与摄影构图。只有画质通过后，再以保留画质为约束处理 KTX2、远景预计算打包、可见性分块、资产分级和传输预算。

没有足够证据要求直接切换整站到 Splat / NeRF，或仅交离线电影。若路线 A 在严格限定的镜头内多轮资产迭代仍达不到视觉目标，才按 Phase 00 的备选路线做受控对照实验，并分别检查相机自由度、透明水体、光照一致性与浏览器兼容性。
