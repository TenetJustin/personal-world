# Phase 01 · 视觉问题与修复记录

判定主体分开：自动化技术测试检验运行、坐标、数据与许可完整性；以下为开发过程的视觉自查。用户的人工视觉验收仍为 **待进行**。不存在自动宣布照片级合格的结论。

## 本轮实际修复

| ID | 浏览器中发现的问题 | 处理 | 复查结果 / 限制 |
|---|---|---|---|
| F01 | 初始 4.5% 树木简化导致针叶轮廓破碎、树冠过稀 | 中档改为 12%，近档 50%，增加真实源网格实例与远景代理密度 | 林冠改善；单一 C 变体与针叶边缘仍显重复 / 闪烁风险 |
| F02 | 草叶呈黑色面片，部分针叶轮廓不成立 | 发现原 glTF JPG 缺少独立 Alpha；补齐官方遮罩，真实 RGBA 合并，MASK + Alpha-to-coverage | 可见黑色矩形被消除；细草仍有采样锯齿 |
| F03 | 压缩后岸石变成异常折叠 / 方块，树高异常 | 根因是量化 Int16 坐标在米制变换时溢出；先展开 Float32 再烘焙世界变换 | 实际浏览器形状恢复，回归测试通过 |
| F04 | 木门、甲板缺少近景材质尺度 | 加入物理 UV、门板接缝、五金、真实端面与 Cycles AO | 近景可辨；端面、基础和屋檐仍欠缺制作级细节 |
| F05 | 原始 2K 全景在窄视角内远山模糊 | 高档使用经校验的官方 4K 全景，保留标准档 2K 对比 | 清晰度改善，传输体积显著超预算；还不是合格资产优化 |
| F06 | 近岸大量平整干燥裸地，前景不足 | 增加曲岸、浅滩、起伏与局部网格密度，草丛替换为较完整变体，按尺度调整并避免埋入土中 | 有改善；仍缺少成片苔藓、根系、地被和湿度边界细节 |
| F07 | 初始取景木屋居中、前景陆地过多 | 固定 A 为 (6,2.6,34)、目标 (-8,4,0)、48°，保持左水右屋；B 单独构图 | 形成两个可重复镜头；背景匹配仍待修正 |
| F08 | 反射目标使用普通 8bit 容易裁剪 HDR 高光 | 反射目标改半浮点，高档增加 2×MSAA，最终统一 AgX | 技术流程修正；并不代表水体照片级通过 |
| F09 | 调整路径后会靠近一棵前景树干 | 将该树移到 (13,25)，对整条曲线 1001 点检查地面、木屋与树干净空 | 几何净空通过；需结合实际录屏判断枝叶和摄影连续性 |
| F10 | AO 在背光一侧过重，木屋变黑 | 实时 AO 强度降为 0.35；环境与直射方向保持一致 | 避免明显黑洞，未靠 Bloom / 浓雾 / 景深掩盖材质 |

## 未关闭的阻塞项

V01：优先重做近岸地表与林下层，加入合法高质量的苔藓地块、枯枝、根系、低矮灌木，以及按湿度 / 光照分布的草群。不要继续增加其他网站功能。

V02：替换或重新制作远山 / 林缘接合资产，遮掉摄影源中的农业景观与近景不一致的地貌；需要局部三维山体或经验证的预计算组合。全景只有摄影远景作用，不能据此宣称完整三维山谷。

V03：增加针叶树轮廓和年龄变体，改善中远景叶片采样和重复感。按当前两镜头采购 / 选择有许可来源的定制植物包，比盲目增加实例数量更合理；本轮没有擅自付费。

V04：封闭窗的高金属度反射近似不符合完整介质玻璃光学，需要修复。建筑仍缺少真实磨损、接缝、端面裂纹、屋檐细节及更好的基础材质。AO 和木纹贴图不能替代这些细节。

V05：高档 4K HDR 与真实树网格传输过大，且 WebP 尚未降低 GPU 展开后的纹理占用。下一轮要保留画质地重做远景、树和纹理导出，不能以降低形状质量换通过。

因此，本轮形成了可审查的技术样片，但未达到“接近真实摄影”的首要验收门槛。不得据此进入室内、桌面系统或其他 Phase 02 功能。

## 保留画质的阴影优化

固定太阳、木屋和树木全部为静态阴影投射者，草不投射动态阴影。因此将太阳阴影改为首次生成后缓存，无需每帧重绘。优化前后 A / B 的实际浏览器 PNG 在同一相机 / 相位下分别逐像素一致（每张 5,184,000 个通道差异为 0）；原始 hash 与对比结果保存在 `tests/shadow-cache-pixel-comparison.json`。这只证明该优化没有改变 A 的画面，不能被解释为画面本身达到照片级。
