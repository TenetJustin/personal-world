# V2 个人资料系统与发布操作

2026-10-25。本次保留原有四个应用、IndexedDB 和完整备份功能。网站发布和个人资料公开是两个不同动作：网站可上线，资料仍默认是此浏览器的本地草稿。

## 添加和整理自己的资料

进入任一应用后，选择“本地草稿”。所有保存操作写入当前站点来源下的 `personal-world-library` IndexedDB，不发送到服务器，不需要账户或 GitHub Token。

- **Notes**：新建或批量导入 Markdown / TXT，编辑正文、标签、分类和排序值；列表可按分类筛选，并按标题、创建时间、更新时间、自定义顺序排列。单篇可导出 Markdown。
- **Photos**：一次最多导入 100 张 JPEG、PNG、WebP 或 GIF；默认保留附件原文件（包括 GIF 动画），并生成长边最多 360 px、质量 0.76 的缩略图。可明确勾选“导入时压缩为 WebP（不保留原文件）”，转换为长边最多 2400 px、质量 0.88 的阅读图；该选项会移除 EXIF，并将 GIF 转为静态照片。旧版资料中的附件不会被重新压缩。编辑标题、照片说明、标签、相册和排序值。相册在列表筛选框中选择。
- **Projects**：填写名称、介绍、分类、技术栈、GitHub、Demo 和其他项目网址；编辑界面批量添加最多 12 张封面 / 截图，第一张作为封面。可前移或移除图片；图片同样生成压缩版本和缩略图。列表支持自定义排序值。
- **Resume**：保留原有 Markdown 正文，同时增加个人简介、教育、实习与工作、项目、技能、荣誉六个结构化部分；允许添加、替换或移除可选 PDF。可导出 Markdown 或下载 PDF，完整备份同时保留两者。

所有应用可将资料移入回收站并恢复。每个附件最大 25 MB；整个资料库最多 5000 项 / 100 MB（包括回收站、正文和缩略图）。图片压缩发生在当前浏览器内。

## 从旧 MVP 迁移

旧版本使用的数据库名称和 `entries` store 保持不变，仍为 IndexedDB v1。新增字段可选，不升级、不删除、不重建数据库，原 ID、时间、正文和 Blob 附件保持原样。

同一来源访问升级网站会直接读到原数据。**localhost、GitHub Pages、自定义域名和不同浏览器属于不同存储空间**：更换来源前请导出完整备份，在目标来源通过“恢复备份”选择文件、查看数量并确认合并。支持旧 v1 和新 v2 备份。相同 ID 使用备份版本替换，其他本地记录保留；恢复操作在一个 IndexedDB 事务中校验配额并写入。

## 备份与恢复

“导出全部备份”生成 `personal-world-YYYY-MM-DD.json`。v2 包含全部四类资料、回收站、结构化履历、压缩照片、缩略图、项目截图和 PDF。它**可能包含私密资料，不能提交到 Git 或当作公开内容包**。请保存在个人安全位置。

恢复备份不会上线内容。恢复完成后请检查关键正文和附件，并在需要时重新选择、审核和导出公开版本。

## 公开内容的完整闭环

1. 保存正在编辑的资料，切到“本地草稿”，点击“审核公开内容”。
2. 在各应用完整阅读准备公开的正文，检查姓名、联系方式、照片中的隐私、截图、PDF、链接、使用权等实际内容。发布面板展示标题、正文开头和附件名称作为选项摘要；它不替代完整审核。
3. 只勾选可以公开的记录。公开范围为这条记录的全部已保存内容与附件。不要选择仍含私密字段的记录；需要时先创建一条删减后的公开版本。
4. 勾选明确审核确认，再点击“导出已审核公开内容包”。生成 `personal-world-public-package.json`。**这一套选择会替换整套网站公开资料；未选中的旧公开记录会在下次导入后移除。** 浏览器保存草稿、生成内容包都不会自动更新网站。
5. 在本地仓库执行：

   ```sh
   node scripts/import_public_content.mjs /完整路径/personal-world-public-package.json
   ```

   脚本只接受带审核时间的公开格式；完整备份被拒绝。它校验字段白名单、ID、类型、网址、附件大小和文件头，先完整校验，再输出 `public/content/manifest.json` 及按 SHA-256 命名的独立图片 / PDF。未被此次选择引用的旧静态附件移除。正文保存在 JSON 字符串中，由 React Markdown 阅读器转义显示，不解释 HTML。
6. 执行项目测试与构建，查看 `git diff -- public/content`，确认只有已批准公开的资料。将这份静态目录提交并推送工作分支。GitHub Actions 自动集成这些受版本管理的文件并部署。
7. 用另一浏览器访问网站，切到“已发布内容”，验证正文、照片、项目详情和 PDF。全新浏览器存在公开内容时默认显示发布版本，不依赖作者的 IndexedDB。

发布包可包含大量图片，建议不要把生成的中间 JSON 同时提交到仓库。只提交导入脚本输出的 `public/content` 文件。

## 取消发布

在本地草稿中重新选择需要保留的所有公开记录，导出并导入新包，再提交和部署。取消发布全部内容时，将 `public/content/manifest.json` 的 `records` 置为空数组、`publishedAt` 更新为当前 ISO 时间，并移除 `public/content/assets` 中的附件，再运行公开内容校验和构建。取消发布只能移除当前网站版本，不能撤回其他人已经下载或 Git 历史中已有的内容；提交前的人工检查是公开资料的关键门槛。

## 当前公开资料状态

当前只发布原创站点使用说明。没有虚构的个人履历、测试人物、私人照片或私人备份。Photos、Projects、Resume 保留清楚的空状态，等待作者审核真实资料后发布。

## 技术接口

- `Library` 保留原有回调，新增可选 `published?: Entry[]`；发布内容只读，本地草稿与发布版本分开展示，不自动写入 IndexedDB。
- `loadPublishedContent(base = SITE_BASE)` 读取同源 `content/manifest.json` 和受限相对资源路径，返回经验证的 `Entry[]`。失败由 App 展示可重试提示，本地资料库继续工作。
- `createPublicPackage(entries, selectedIDs, reviewed)` 只复制允许公开的数据字段，不包含本地回收站字段，不会遍历未选中的记录。
- `scripts/import_public_content.mjs` 也导出 `validatePublicPackage` 与 `importPublicPackage`，供测试与导入校验使用。
- 公开清单格式 `personal-world-published` / v1，记录数组键为 `records`；附件字段保留 `attachment` / `thumbnailData`，值改为 `assets/<SHA-256>.<扩展名>`。
- 路由使用 `src/site.ts` 统一 base，详情使用 `/notes/?id=...`，避免 Pages 动态路由 404；旧 `/notes/id/` 本地解析仍兼容。PDF.js 字体、cMap、WASM 和 worker 使用相同构建 base。

## 验证与限制

单元测试覆盖公开选择、审核必须显式确认、私密草稿排除、回收站排除、备份误用拒绝、白名单字段、恶意网址、无效文件头、静态附件哈希、实际落盘导入、v1 迁移、v2 结构化字段恢复。独立 HTTP 往返测试已将原创夹具的审核包导入 `work/sprint-v2/public-roundtrip/content`，通过实际 localhost HTTP 和 `/personal-world/` 子路径读取四类记录，检查三份独立附件 SHA-256、PDF 字节、项目图片和结构化履历，确认未选择的私密标记未进入公开清单。正式 `public/content/manifest.json` 只包含在真实浏览器创建、勾选审核并导出的原创站点说明，不包含测试夹具或真实私人资料。原始报告为 `work/sprint-v2/content-roundtrip-report.json`。

浏览器层的完整 CRUD、图片编码、PDF 阅读、实际导出文件、另一浏览器读取和部署刷新由 Sprint 集成验证报告记录；不能将单元测试视为已经完成这些浏览器验收。

本版本没有账户、服务器数据库或访客写入 API。作者在别的浏览器编辑，仍需要备份迁移。图片使用 WebP，未实现原图分级流式加载、完整 EXIF 查看或复杂相册编排；Markdown 阅读器为既有的安全基础子集。大批公开附件首次加载会增加下载量，后续可改为详情按需加载。不要将未完成的这些优化误写为已完成。
